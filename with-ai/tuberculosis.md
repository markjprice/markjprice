# Intelligence Is Not Wisdom: What John Green’s Tuberculosis Argument Can Teach Us About AI

Artificial intelligence has made it easier than ever to generate answers. That is useful, but it also creates a trap. We can start to confuse answer-generation with understanding, and understanding with judgment.

John Green’s work on tuberculosis gives us a powerful way to think about that distinction.

Green’s argument, in simplified form, is this: tuberculosis is not still one of the world’s deadliest infectious diseases because humanity lacks intelligence. We know what tuberculosis is. We know how it spreads. We have diagnostic tools. We have treatments. We have decades of medical knowledge.

And yet tuberculosis still kills huge numbers of people, mostly in poorer communities and places with weaker access to healthcare. That makes tuberculosis more than a medical problem. It is also a social, political, economic, and moral problem.

Green’s point is not that science has failed. His point is that knowledge alone is not enough. Intelligence can discover a cure. Wisdom asks who receives it, who pays for it, who is ignored, and why suffering continues when solutions already exist.

That distinction is useful far beyond public health. It is especially useful when thinking about AI.

## AI can be intelligent without being wise

An AI coding assistant can do extraordinary things.

It can:

- generate a function;
- explain an error message;
- suggest a refactoring;
- summarize documentation;
- compare two approaches;
- write tests;
- draft HTML, CSS, JavaScript, SQL, or Python;
- help you understand unfamiliar code.

That is intelligence in a practical sense. The system can process patterns, produce plausible answers, and help you move faster.

But that is not the same as wisdom.

Wisdom asks different questions:

- Is this the right problem to solve?
- Is this code understandable by a beginner?
- Is this solution maintainable?
- Is this accessible to users with disabilities?
- Does this handle bad input safely?
- Does this expose private information?
- Does this make the system easier or harder to debug?
- What assumptions is this answer making?
- Who benefits if we build it this way?
- Who might be excluded or harmed?

Those are not just coding questions. They are judgment questions.

## The danger of treating intelligence as authority

Beginners are especially vulnerable to a common mistake: assuming that because an AI answer looks confident, it must be correct.

Generated code often looks tidy. It may use sensible names. It may include comments. It may resemble examples from documentation. It may even run successfully for the first test case.

But code can be polished and still wrong.

It might:

- ignore edge cases;
- use outdated APIs;
- introduce security problems;
- be too complicated for the task;
- fail silently;
- handle only the example you gave it;
- solve a slightly different problem from the one you intended;
- teach you a pattern you do not yet understand.

The problem is not that AI is useless. The problem is that useful tools can still be misused.

A calculator can help you do arithmetic, but it does not know whether you are calculating the right thing. A spellchecker can find typos, but it does not know whether your argument is sound. A satnav can suggest a route, but it does not know whether you should make the journey.

In the same way, an AI coding assistant can help you write code, but it cannot take responsibility for your understanding.

## The sidekick model

That is why this book uses the idea of an AI sidekick.

A sidekick helps. A sidekick notices things. A sidekick offers alternatives. A sidekick asks questions. A sidekick sometimes saves time.

But the hero still has to make decisions.

When you use AI while learning web development, the goal is not to skip the thinking. The goal is to get better support while thinking.

A useful AI sidekick can help you:

- turn a vague question into a clearer one;
- break a large task into smaller tasks;
- compare two possible implementations;
- explain code line by line;
- suggest tests;
- review your work;
- help you recover from errors;
- point you toward documentation;
- ask you questions that reveal gaps in your understanding.

That is the kind of assistance that helps you grow.

The unhelpful version is different. It looks like this:

> Write the whole thing for me.

That prompt may produce code, but it often produces dependency. You get an answer without a path. You get output without understanding. You get movement without direction.

A better prompt is:

> Do not write the full solution yet. Explain the problem, show me a small example, ask me one question to check my understanding, and then help me implement the next small step.

That prompt uses AI as a teacher, reviewer, and sidekick.

## Verification is where wisdom begins

The easiest way to improve your use of AI is to add verification.

Do not ask only:

> Did the AI give me code?

Ask:

> How do I know this code works?

That one question changes everything.

For a web developer, verification might mean:

- running the code;
- reading the generated code line by line;
- checking the browser console;
- using the debugger;
- writing tests;
- trying invalid input;
- checking accessibility;
- comparing the answer with official documentation;
- asking the AI to explain trade-offs;
- asking another AI model for a review;
- simplifying the answer until you understand it.

Verification turns AI from a code vending machine into a learning partner.

It also keeps you honest. If you cannot explain what the code does, you are not finished yet.

## Intelligence builds. Wisdom chooses.

AI will keep getting better at generating code. It will get better at fixing errors, producing examples, and working across larger projects.

That is valuable.

But as AI becomes more capable, human judgment becomes more important, not less. Someone still has to decide what should be built, why it should be built, how it should behave, what risks matter, what quality looks like, and when the answer is good enough.

This is the deeper lesson from John Green’s tuberculosis argument. Intelligence can produce knowledge. Intelligence can produce tools. Intelligence can produce treatments, tests, systems, and code.

Wisdom asks whether we are using those things well.

For a beginner learning web development, that means using AI with curiosity and caution. Let it help you. Let it explain. Let it suggest. Let it challenge you.

But do not hand over your judgment.

The goal is not to become someone who can copy AI-generated code.

The goal is to become someone who can understand, question, test, improve, and responsibly use the code that AI helps create.
